# v0.80.0 release signing + verification

The `v0.80.0` source tarball (`helpmefindthejob-0.80.0.tar.gz`, attached to the GitHub Release) is cryptographically signed with [cosign](https://docs.sigstore.dev/cosign/overview/). This page documents (a) the operator-side signing recipe and (b) the downstream verification commands a NLnet reviewer or re-distributor can run.

**Status at planning time** (2026-05-24): cosign signing is operator-gated — the operator tags release v0.80.0 and regenerates the cosign signature. The CHANGELOG cut + release notes + SBOM landed in the agent-prep batch; the operator runs the signing chain below.

---

## Automated path (preferred, since 2026-05-24)

A release workflow at `.github/workflows/release.yml` triggers on push of a `v*` tag and runs the cosign sign-blob + SLSA-Level-2 provenance attestation + SBOM generation + GitHub Release creation chain in one pass. The maintainer just runs:

```bash
git tag -s v0.80.0 -m "Helpmefindthejob v0.80.0 — NLnet NGI Zero Commons Fund submission state"
git push origin v0.80.0
```

…and the workflow takes it from there. Sign-blob uses keyless OIDC (no maintainer private key flows through workflow secrets). SLSA provenance is attached as `v0.80.0-provenance.sigstore` alongside the `v0.80.0-source.tar.gz.sigstore` bundle. Downstream verification recipe is in the workflow's summary step + the §"Downstream verification" section below — the only change vs the manual flow is the `--certificate-identity-regexp` pattern, which becomes `https://github.com/.*/release.yml@.*` for keyless verification (the manual long-lived-key path stays as `--key v0.80.0-cosign.pub`).

The manual operator recipe below remains the documented fallback for environments where the GitHub Actions runner is not available or where the maintainer wants to use a long-lived ECDSA key model instead of keyless OIDC.

## Operator signing recipe (manual fallback)

Run this once after the v0.80.0 tag is cut. The maintainer has the cosign private key (or uses the GH-Actions OIDC keyless path).

### Step 1 — cut the signed git tag

```bash
# Confirm you are at the right commit
git checkout main
git pull --ff-only
git log -1 --oneline
# Should show the commit that closes the agent-doable Ceiling-1 work
# (e.g. 06b7582 GRANT-1.3.5 + 2.10.6 or later)

# Cut the signed tag (GPG-signed; requires `git config user.signingkey` set)
git tag -s v0.80.0 -m "Helpmefindthejob v0.80.0 — NLnet NGI Zero Commons Fund submission state"
git push origin v0.80.0
```

If GPG is not configured, fall back to an annotated unsigned tag:

```bash
git tag -a v0.80.0 -m "Helpmefindthejob v0.80.0 — NLnet NGI Zero Commons Fund submission state"
git push origin v0.80.0
```

The cosign signature below covers the source tarball bytes regardless of whether the tag itself is GPG-signed; both layers strengthen the chain.

### Step 2 — build the source tarball

```bash
# Create the canonical source archive with the helpmefindthejob-0.80.0/ top-level dir
git archive --format=tar.gz --prefix=helpmefindthejob-0.80.0/ \
  -o helpmefindthejob-0.80.0.tar.gz v0.80.0

# Record the SHA-256 for the release notes table
sha256sum helpmefindthejob-0.80.0.tar.gz
# Capture this output and paste into docs/releases/v0.80.0.md "Signed artefact" table
```

### Step 3 — cosign sign-blob

Two paths; choose one.

**Path A — long-lived ECDSA P-256 key pair** (matches v0.1.0 model b):

```bash
# Generate the key pair if you do not have one (one-time)
cosign generate-key-pair
# Writes cosign.key (private; protect) + cosign.pub (public; commit)

# Sign the tarball
cosign sign-blob --key cosign.key --bundle v0.80.0-source.tar.gz.sigstore \
  helpmefindthejob-0.80.0.tar.gz

# Move the artefacts to docs/releases/
mv v0.80.0-source.tar.gz.sigstore docs/releases/
cp cosign.pub docs/releases/v0.80.0-cosign.pub

# Commit the public key + bundle + SBOM
git add docs/releases/v0.80.0-cosign.pub \
        docs/releases/v0.80.0-source.tar.gz.sigstore \
        docs/releases/v0.80.0-sbom.json \
        docs/releases/v0.80.0.md \
        docs/releases/v0.80.0-signing.md
git commit -m "v0.80.0 release artefacts: cosign signature + public key + SBOM"
git push origin main
```

**Path B — keyless via GitHub Actions OIDC** (matches the v0.2.0+ plan):

```bash
# On a GitHub Actions runner authenticated for this repo:
cosign sign-blob --bundle v0.80.0-source.tar.gz.sigstore \
  helpmefindthejob-0.80.0.tar.gz
# The bundle includes the ephemeral certificate; the public key is anchored
# in the Sigstore Fulcio root trust.
```

The two paths produce verifiable signatures; Path A is the simpler downstream-verification story (no Sigstore trust-root dependency); Path B has zero-private-key-handling-burden.

### Step 4 — attach assets to the GitHub Release

```bash
gh release create v0.80.0 \
  --title "Helpmefindthejob v0.80.0 — NLnet submission state" \
  --notes-file docs/releases/v0.80.0.md \
  helpmefindthejob-0.80.0.tar.gz \
  docs/releases/v0.80.0-source.tar.gz.sigstore \
  docs/releases/v0.80.0-cosign.pub \
  docs/releases/v0.80.0-sbom.json
```

## Downstream verification (reviewer side)

A NLnet reviewer, a re-distributor, or any downstream auditor runs this to verify the tarball came from the maintainer and matches the tagged commit.

```bash
# 1. Download the release assets
gh release download v0.80.0 --repo maksodf/helpmefindthejob \
  --pattern 'helpmefindthejob-0.80.0.tar.gz' \
  --pattern 'v0.80.0-source.tar.gz.sigstore' \
  --pattern 'v0.80.0-cosign.pub' \
  --pattern 'v0.80.0-sbom.json'

# 2. Verify the cosign signature (Path A — long-lived key)
cosign verify-blob \
  --key v0.80.0-cosign.pub \
  --bundle v0.80.0-source.tar.gz.sigstore \
  --insecure-ignore-tlog \
  helpmefindthejob-0.80.0.tar.gz
# Expected: "Verified OK"

# 3. Verify the SHA-256 matches the release notes table
sha256sum helpmefindthejob-0.80.0.tar.gz
# Compare against docs/releases/v0.80.0.md "Signed artefact" table

# 4. Verify the SBOM round-trips
python3 -c "import json; d=json.load(open('v0.80.0-sbom.json')); print(f'spec={d[\"specVersion\"]}'); print(f'components={len(d[\"components\"])}')"
# Expected: spec=1.6, components=8 (direct deps from requirements.txt)
```

The `--insecure-ignore-tlog` flag skips the transparency-log lookup (the v0.1.0 release was the same; it's a "we don't depend on Rekor for this long-lived-key model" choice). If you prefer the transparency-log check, drop the flag — cosign will look up the signature in the Sigstore Rekor instance.

## Transitive-closure SBOM (operator-optional)

The shipped SBOM (8 components) covers the direct dependencies in `requirements.txt`. To produce a transitive-closure SBOM (~90 components, matching the v0.1.0 shape) the operator runs:

```bash
# Build a clean venv with only the runtime requirements
python3 -m venv /tmp/v0.80.0-sbom-venv
/tmp/v0.80.0-sbom-venv/bin/pip install -r requirements.txt
# Generate the SBOM against the installed env
cyclonedx-py environment --pyproject /tmp/v0.80.0-sbom-venv \
  -o docs/releases/v0.80.0-sbom-full.json \
  --output-format json --spec-version 1.6
```

This is a separate deliverable from the v0.80.0-sbom.json shipped in the release; we ship the direct-dependency version because (a) it is reproducible from `requirements.txt` alone, and (b) downstream auditors typically want the maintainer-declared deps, not the transitive Python-ecosystem closure.

## Signing-key model

| Field | Value |
|---|---|
| Algorithm | ECDSA P-256 |
| Key rotation cadence | Per major version (v1.0.0 will get a fresh key); the v0.80.0 key remains valid for any v0.8x.y signature |
| Compromise procedure | Rotate immediately (cosign-generate-key-pair → re-sign all in-life artefacts → publish revocation note in CHANGELOG); see `compliance/audit-log-key-rotation.md` for the broader key-lifecycle pattern |
| Private-key storage | Maintainer's offline encrypted backup; the unencrypted form never touches a network-attached host |
| Public-key publication | `docs/releases/v0.80.0-cosign.pub` (in-repo) + attached to the GitHub Release |
| Reproducibility | All steps above are scriptable; the SBOM + tarball are bit-reproducible from the tagged commit |

## Provenance attestation (operator-optional)

For SLSA Level 2 provenance, the operator can also generate a build-provenance attestation:

```bash
cosign attest --key cosign.key \
  --predicate <(echo '{"buildType":"github-archive","commit":"'$(git rev-parse v0.80.0)'","timestamp":"'$(date -u +%Y-%m-%dT%H:%M:%SZ)'"}') \
  --bundle v0.80.0-provenance.sigstore \
  --type slsaprovenance \
  helpmefindthejob-0.80.0.tar.gz
mv v0.80.0-provenance.sigstore docs/releases/
gh release upload v0.80.0 docs/releases/v0.80.0-provenance.sigstore
```

This is optional for v0.80.0 (it strengthens the supply-chain story but is not a NLnet gate). It's queued for the post-grant 1.0 release (privacy / security / incident-readiness; see `docs/grant/03-post-grant.md`).
